# Basic Metrics Subsystem (`src/evaluation/`)

## 1. Overview & Purpose
The `src/evaluation/` subsystem provides the **Basic Metrics** calculation engine for the quantitative trading research system.
It takes an immutable, read-only `BacktestResult` payload generated by `src/backtest/` and computes Phase 1 performance metrics without running backtests or mutating state.

## 2. Architecture & Design Principles
- **Read-Only / Pure Functionality**: Operates strictly downstream of `BacktestResult`. Does NOT access Market Data, Strategy, Execution, Broker, Clock, or Portfolio directly.
- **Immutable Container**: `BasicMetrics` is a `@dataclass(frozen=True)` holding calculated statistics and an immutable equity curve.
- **Strict Data Validation**: Validates `initial_capital > 0` before computing return percentages, raising `InvalidEvaluationError` if violated.
- **Deterministic Metrics**: Computes trade count and win rate by analyzing realized PnL delta transitions across `portfolio_history` snapshots.

## 4. Usage Example

```python
from src.backtest.engine import BacktestEngine
from src.evaluation import BasicMetrics, calculate_basic_metrics

# 1. Run backtest engine to produce result
result = engine.run(dataset_id="BTCUSD_M15", df=df)

# 2. Compute basic evaluation metrics
metrics = calculate_basic_metrics(result)
# Or alternative factory method:
# metrics = BasicMetrics.from_result(result)

# 3. Access calculated performance statistics
print(f"Initial Capital : ${metrics.initial_capital:,.2f}")
print(f"Final Equity    : ${metrics.final_equity:,.2f}")
print(f"Net PnL         : ${metrics.net_pnl:,.2f} ({metrics.return_pct:.2f}%)")
print(f"Trade Count     : {metrics.trade_count}")
print(f"Win Rate        : {metrics.win_rate:.2f}%")
```

## 6. Equity Performance and Risk Kernel

`calculate_equity_risk_metrics(equity_curve, timeframe, risk_free_rate=0.0)` evaluates only chronological equity snapshots. It returns net PnL, return, CAGR, maximum drawdown in currency and positive percentage magnitude, drawdown duration, annualized volatility, Sharpe, Sortino, and Calmar.

Annualization is derived from the supplied `Timeframe` for a 24/7 crypto market (`M15=35040`, `H1=8760`, `H4=2190`, `D1=365` periods/year). Undefined Sharpe, Sortino, or Calmar values are `None`; invalid equity curves raise `InvalidEvaluationError`.

Trade-level metrics such as round-trip win rate, profit factor, R-multiple, MAE/MFE, and cost attribution are deliberately not inferred from portfolio snapshots. They require a future `TradeLedger` owned by the trading layer.

## 7. Accounting Reconciliation

`calculate_accounting_reconciliation(result)` makes the final-equity ledger explicit:

```text
account_equity = initial_capital + realized_pnl - fees - funding
final_equity   = account_equity + unrealized_pnl
```

The returned residual must be numerically zero for a consistent strict `BacktestResult`. `run_backtest.py` renders this breakdown before its performance and risk metrics.
